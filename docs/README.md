## 当前实现概览

当前仓库已经具备以下基础能力：

- FastAPI 后端、MySQL 迁移、MinIO 对象存储、Redis Session/锁、父块正文三级缓存和 Elasticsearch 检索基础。
- 顾客/员工登录、服务端 Session、HttpOnly Cookie、密码哈希升级和部分 Session 撤销能力。
- 当前车主 `my_car.user_id` 范围查询、员工 `staff/leader` 权限判断和文档审核队列。
- PDF、DOC、DOCX 的 MinerU 解析与 CSV/Excel 的 Markdown 表格转换、可选切片策略（TITLE/LENGTH/SMART/REGEX/SEPARATOR）、Embedding 和 Elasticsearch 向量写入。
- 意图识别、查询改写、数据源路由、ES 混合召回、RRF、父子块补全、二次授权、结构化源回落知识库、rerank 和 qwen3.7-plus 流式回答。
- 多轮记忆：按窗口读取最近 10 条已持久化消息，按字符预算裁剪后拼入提示词，读取失败只降级为无历史。
- 回答引用、赞踩反馈、基础任务状态、重试、DLQ 接口和 Python 代码分析沙箱。
- 最小 Next.js Web 页面：登录、提问、SSE 展示、文档上传/审核和反馈。

## 端到端逻辑

### 知识入库

```text
员工上传文件
  → 文件校验并保存原文件
  → MinerU 异步转换为 Markdown
  → 按标题、段落和长度生成父子分块
  → 保存文档/版本/状态/分块元数据到 MySQL
  → leader 审核并设置 VISITOR、STAFF 或 LEADER
  → text-embedding-v4 生成 1536 维向量
  → 写入 Elasticsearch 向量、全文和 metadata 索引
```

### 问答

```text
用户提问
  → FastAPI 从服务端 Session 构造身份与权限上下文
  → 读取该会话最近 N 条已持久化消息并按字符预算裁剪（读取失败降级为无历史）
  → qwen3.5-flash 意图识别、查询改写和路由
  → 按白名单并行检索 ES、受控 MySQL 或公开 Neo4j
  → 结构化源无证据或故障时回落一次知识库检索并记录 fallbacks 审计
  → RRF 融合
  → MySQL 二次授权、父块三级缓存（请求内 → Redis → MySQL）和上下文预算控制
  → qwen3-rerank 重排（不可用时安全降级为 RRF 结果）
  → qwen3.7-plus 基于已授权证据生成 SSE 回答和引用
  → 持久化成功回答、引用、反馈和 trace_id
```

核心安全原则是：权限先于检索，FastAPI 是唯一可信边界；浏览器、模型和 Agent 不直接访问业务数据库或搜索基础设施。

## 当前已知缺口

以下内容仍不能在 GitHub 文档中表述为“已完成”：

1. **可靠任务生产验收仍需完成**：任务配置和 Celery 入口已补齐，但预生产 Phoenix、网络分区、慢任务和 DLQ 混沌验收仍需部署环境验证。
2. **Agent Runtime 尚未独立落地**：当前问答编排主要仍在 FastAPI 进程内，`apps/agent_runtime/` 还是目标架构。
3. **API 版本迁移已提供兼容前缀**：业务接口同时挂在 `/api/*` 与 `/api/v1/*` 下；
   后续仍需确定正式版本策略与废弃时间表，并对 OpenAPI 与 SSE 契约做持续校验。
4. **SSE 契约已补齐基础六类事件**：仍需在 CI 中持续运行契约校验，确保新增字段不与运行时分叉。
5. **Web 功能仍是最小闭环**：会话列表、历史读取、文档内容预览等页面能力尚未完成；当前前端 README 已明确列出边界。
6. **文档格式和生命周期仍不完整**：上传链路已支持 PDF、DOC、DOCX 的 MinerU 解析与 CSV/XLS/XLSX 的 Markdown 表格转换，
   但独立表格切分模式、文档版本切换、归档与删除仍未落地。
7. **员工业务数据查询范围有限**：当前已有当前车主 `my_car` 受控查询，员工受控业务视图和更完整的内部工具契约仍需实现。
8. **统一错误、可观测性和生产验收仍需加强**：部分接口仍返回简单 `detail`，结构化脱敏日志、指标、告警和混沌测试尚未形成完整闭环。
9. **模型版本治理仍需完善**：默认模型已统一为需求规定值，但生产环境仍需固定镜像/模型版本并完成配额、出境和预算确认。
