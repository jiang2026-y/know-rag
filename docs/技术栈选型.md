# 汽车企业知识管理与智能问答系统技术栈选型

> 文档状态：已确认选型，含实施前决策门｜更新时间：2026-08-04
>
> 本文以《需求规格说明书》和《技术要求与目录评估》为依据，记录当前项目的技术选型、边界和约束。本文不授权直接修改数据库 Schema、接入生产密钥或部署基础设施；这些变更仍须经过相应评审。

## 1. 结论先行

项目采用 **Next.js Web 前端 + Python 模块化单体业务后端 + 独立 Agent 运行时** 的架构。`api_service` 是身份、权限、业务数据和审计的唯一可信边界；`apps/web` 仅负责页面展示、浏览器交互和 SSE 消费；`agent_runtime` 通过同步 HTTP/JSON 调用受控工具，不直连 MySQL、Elasticsearch、Redis、MinIO 或 Neo4j。

| 层次 | 已选技术 | 用途与约束 |
| --- | --- | --- |
| 运行时 | Python 3.11–3.13；生产建议统一 Python 3.13 | `relier` 要求 Python 3.11+；现有 Docker 代码分析沙箱保持 Python 3.13。 |
| Web 前端 | Next.js App Router、React、TypeScript | P0 仅提供 Web 界面；页面、会话交互、SSE 消费与引用展示调用 FastAPI 的版本化 API，不直连数据源、模型或 Agent 工具。 |
| 业务后端 | FastAPI、Pydantic、Uvicorn | 提供版本化 HTTP API、认证、知识管理、会话和 SSE；Controller 不承载 RAG 编排。 |
| Agent | 独立 `agent_runtime`，HTTP/JSON 受控工具 | 承担意图、改写、工具选择、检索编排、重排、上下文组装和流式回答；仅持有模型与内部服务的最小凭证。 |
| 关系数据 | MySQL + SQLAlchemy + Alembic | 业务事实源、员工账号及其 `status`、`job`、`dept_id` 权限数据、会话、任务与审计；Alembic 是唯一生产 Schema 变更入口。 |
| 图数据 | Neo4j | 员工权限、车型、知识域及车主关联的关系图谱；不得成为唯一可信身份源或绕过业务后端授权。 |
| 知识检索 | Elasticsearch | 中文全文、1536 维向量和 metadata 混合检索；在召回前执行知识可见范围过滤。 |
| 对象存储 | MinIO（本地）+ S3 兼容对象存储（生产） | 存储原文件、Markdown、图片与解析产物；仅通过经授权的短时预签名链接访问。 |
| 文档解析 | MinerU Precision Extract API | 将受支持文档转换为 Markdown；解析失败的文档不得进入可检索状态。 |
| 模型平台 | 阿里云百炼 / DashScope | 模型调用通过 Adapter/Gateway 隔离，密钥只保存在服务端 Secret 或 `.env`。 |
| 可靠异步任务 | Celery 5.4+ + Redis 7+ + Relier 0.1 系列 | 处理文档、Embedding、索引、审计等可恢复任务；Redis 必须启用 AOF 且使用 `noeviction` 淘汰策略。 |
| 缓存与会话 | Redis 7+ | 保存服务端 Session、分布式锁及任务状态；Cookie 中不保存身份和权限。 |
| 代码分析沙箱 | Docker + Python 3.13 | 非 root、只读根文件系统、默认无网络、独立容器和临时工作区；仅支持 Python 分析与测试。 |
| 可观测性 | OpenTelemetry + 结构化日志 | 以 `trace_id` 贯穿 HTTP、任务、模型、ES、MySQL、Neo4j 与 SSE；日志必须脱敏。 |

## 2. 总体架构与可信边界

~~~text
Next.js Web（P0） / 钉钉（P1）
  │ HTTPS、SSE
  ▼
api_service（FastAPI）
  ├─ 身份认证、权限计算、业务数据、审计
  ├─ MySQL（事实源） / Elasticsearch / MinIO / Neo4j
  └─ 受控工具 HTTP/JSON
       │
       ▼
agent_runtime
  ├─ 百炼模型调用
  ├─ 意图、改写、检索编排、重排、引用、回答事件
  └─ Celery + Relier Worker / Docker 代码分析沙箱
~~~

- Next.js 前端不得直连数据源、模型服务或 Agent 内部工具；其业务请求只能调用 FastAPI 的 `/api/v1` 契约，内部工具接口不对浏览器公开。
- 任何角色、车辆范围、员工范围和知识范围均由 `api_service` 从可信数据构造；Agent 和客户端提交的同类字段不可信。
- Agent 调用关系库、ES 和 Neo4j 时必须调用受控工具；业务后端负责行列白名单、数据范围、超时、审计和二次授权。
- 现有 `src/llmcopy` 按 `identity`、`knowledge`、`vehicle`、`conversation`、`qa`、`admin` 进行领域垂直切分；新增功能在既定边界内渐进实现。

## 3. 模型选型

| 能力 | Provider | 模型 | 选型目的 |
| --- | --- | --- | --- |
| 意图识别 | 阿里云百炼 / DashScope | `qwen3.5-flash` | 低延迟地输出经 Pydantic 校验的结构化意图。 |
| 查询改写 | 阿里云百炼 / DashScope | `qwen3.5-flash` | 执行术语标准化、纠错和检索查询改写。 |
| 回答生成 | 阿里云百炼 / DashScope | `qwen3.7-plus` | 基于已授权证据生成带引用的回答。 |
| 向量化 | 阿里云百炼 / DashScope | `text-embedding-v4`，1536 维 | 为可检索子块创建向量；维度、模型和版本必须写入索引与分段元数据。 |
| 重排 | 阿里云百炼 / DashScope | `qwen3-rerank` | 对统一证据候选集评分；候选数量、超时与预算可配置。 |

模型输出一律视为不可信输入：意图和工具参数必须经 Pydantic Schema 校验，回答只能引用服务端已确认的 `RetrievedEvidence`。P0 意图结果固定为 `related`、七类 `intent`、八项 `entities` 和不超过 200 字的 `reasoning`；不生成、传输、持久化完整思维链。意图 Schema 或模型调用失败时仅重试一次，随后按非汽车通用对话处理，禁止访问 Elasticsearch 或企业数据。变更 Embedding 模型、维度或版本时必须创建新 ES 索引或受控重建，不得混用向量。

## 4. 数据、检索与身份

### 4.1 MySQL、Elasticsearch、MinIO

- MySQL 是业务事实源，保存文档版本、分段元数据、会话、身份映射、权限快照、任务和审计记录。
- Elasticsearch 负责向量、中文全文和 metadata 混合召回；P0 必须按 `metadata.accessibleBy` 精确过滤 `VISITOR`、`STAFF`、`LEADER`。领导查询范围同时包含 `STAFF`；车型、区域和部门过滤暂不启用。
- Elasticsearch 命中只是可重建投影，不能作为最终授权结论：P0 必须回 MySQL 校验文档当前为 `VECTOR_STORED` 且 `accessible_by` 仍在可信主体范围内。短父块完整回溯；长父块使用命中块与相邻子块的受限窗口补全，再送入回答模型。
- 父块回溯使用三级缓存：请求内字典 → Redis（复用认证 Session 实例，键前缀 `llmcopy:cache:segment:`，TTL 默认 30 秒）→ MySQL。缓存只存正文，不存权限结论；命中后仍需 MySQL 二次授权，重新切片、重新向量化或生命周期变更时立即失效，Redis 故障时退化为回源 MySQL。
- 路由命中关系库或图数据库但两路均无证据（含适配器故障）时，编排层回落一次知识库检索，并在该轮 `retrieval` 审计里记录 `fallbacks: [{from, reason}]`；证据带 `fallback_from:<strategy>` 标记，避免把知识库证据误认为结构化事实。路由置信度低于 0.5 的空路由语义保持不变。
- MinIO 存储私有对象，MySQL 仅保存对象 URI、哈希、版本、状态与元数据。
- 文档处理以 `queued`、`processing`、`converted`、`chunked`、`vector_stored`、`failed`、`cancelled` 的可观测状态机协调三类存储。

### 4.2 Neo4j 与 ID-Mapping

采用“**MySQL 权威映射 + Neo4j 关系图谱**”方案。

~~~text
员工 MySQL 账号（emp_id + 密码） ───┐
车主服务端 Session（可信用户 ID） ──┼→ MySQL 账号、授权与车辆绑定数据（授权依据）
订单 / 车辆 / VIN / CRM 等可信主数据 ─┘                    │
                                                            ▼
                                         Neo4j 组织、车辆与知识关系图谱
~~~

- P0 员工账号及知识权限由 MySQL 业务系统维护：`emp_id` 是稳定标识，`status` 决定是否可登录，`job` 只使用固定值 `staff`、`leader` 区分员工类别；`dept_id` 可维护但暂不参与知识授权，区域和车型范围也不参与 P0 员工授权。
- Neo4j 负责受控关系查询，例如员工—岗位—部门—知识域，或车主—订单—车辆—服务记录。图谱同步滞后、关系不完整或图查询失败时，系统按最小权限降级。
- Neo4j 中员工节点使用 `emp_id` 作为业务唯一标识；写入采用参数化 Cypher 与 `MERGE`；禁止由 Agent 拼接 Cypher。
- `api_service` 必须在图查询结果返回前再次校验 MySQL 映射状态与权限版本，不能将图遍历结果直接视为授权结论。

### 4.3 认证与授权

- 员工认证使用现有 MySQL 员工账号密码；`staff_info.emp_id` 为当前稳定员工标识，`status`、`job`、`dept_id` 由业务系统维护。普通员工固定为 `job=staff`，领导固定为 `job=leader`；禁用或部门变更后，后端必须立即撤销该员工的全部 Redis Session，强制其重新登录并按最新权限构造 `AccessContext`。
- 密码摘要使用 Argon2id（`memory_cost=19456 KiB`、`time_cost=2`、`parallelism=1`、16 字节随机盐、32 字节摘要）；历史 PBKDF2-HMAC-SHA256（600000 次）仅用于兼容登录，校验成功后自动升级。顾客修改密码前先撤销全部 Redis Session，密码写入失败时不留下未撤销的旧登录态。
- HR 创建员工主数据后通过仅内部网络开放的开户接口设置一次性初始密码；接口以 `X-Internal-Service-Token` 鉴权、要求 `Idempotency-Key`，仅接受 `status=ON_JOB` 且密码为空的已有员工，生成 Argon2id 后立即撤销该员工 Redis Session。接口不创建员工、不修改 HR 主数据、不返回或审计明文密码/密码摘要；成功审计保留六个月，幂等记录保留 24 小时。
- 管理员员工访问接口仅允许在职且 `job == "leader"` 的员工调用，且仅能修改当前 `job=staff` 的普通员工 `status`、`dept_id`，不得修改 `job`；必须携带 `Idempotency-Key`，幂等记录保留 24 小时，权限审计记录保留六个月。
- 车主继续使用当前 Redis 服务端 Session + HttpOnly Cookie，不改为浏览器持有 JWT。车辆、订单和服务记录范围必须从可信绑定关系推导。
- P0 车主范围仅由 `my_car.user_id` 与 `user_info.id` 的绑定推导；`car_order.user_id` 仅保留订单归属，不能单独授予车辆访问。共享车辆不进入 P0；后端过户或解绑时更新或清空 `my_car.user_id`，并立即撤销原车主全部 Redis Session。
- 普通顾客、车主、员工的 `AccessContext` 至少包含主体、服务角色、车辆范围、员工范围和知识范围；员工范围在 P0 仅由在职状态和 `job=staff`、`job=leader` 构造，`dept_id` 不参与知识授权。身份或授权服务故障时仅允许公开知识访问。

## 5. 异步任务与可靠性

文档转换、Embedding、索引重建、查询记录和反馈聚合使用 **Celery 5.4+、Redis 7+、Relier 0.1 系列**。Relier 是 Celery 的可靠性层，不替代业务幂等、状态机或审计。

- 使用 `@rl_task` 包装适合异步执行的任务；需要去重的任务显式启用 `idempotent=True`。
- Relier 的 Phoenix 恢复、原子 Redis Lua 幂等、两级超时、SIGTERM 优雅关闭和 DLQ 用于应对 Worker 中断、重复投递、长时间卡死与毒丸任务。
- 任务仍必须使用业务幂等键、MySQL 唯一约束和状态机保证外部副作用安全；Redis Lua 只能原子化 Redis 内操作，不能形成 MySQL、MinIO、ES、Neo4j 或模型 API 的全局事务。
- Redis 需启用 AOF、配置 `maxmemory-policy noeviction`，并运行 Relier resurrector；DLQ 中的任务保留失败原因、重试/复活历史、关联 `trace_id` 和最小必要任务元数据。
- `relier` 处于 pre-1.0 阶段。依赖声明锁定在 `>=0.1,<0.2`，实现时必须在 lockfile 固定通过预生产混沌测试的精确版本；升级前运行其 Worker 中断、网络分区、过载、任务损坏和慢任务测试。

### 5.1 P0 可靠任务参数（已确认并已落地）

- 认证/锁 Redis 与 Celery/Relier Redis 使用独立实例；开发环境任务 Redis 映射本机 `6380`，单节点运行，不承诺 HA。
- 任务 Redis 启用 AOF `everysec` 与 `maxmemory-policy noeviction`；Worker 并发为 1，软超时 15 分钟、硬超时 20 分钟，自动重试最多 3 次。
- DLQ 记录保留 7 天，Celery Beat 定时清理；只有 `job=leader` 的在职员工可以查询和人工重放文档任务死信。
- 每日任务 Redis RDB 备份保留 7 天；备份目录与认证 Redis、业务数据卷隔离。

## 6. 接口、流式响应与沙箱

- 外部 API 使用版本化 HTTP/JSON；问答采用 SSE，提供 `progress`、`query_rewrite`、`answer_delta`、`citation`、`error` 和 `done` 事件。
- 回答生成使用会话级多轮记忆：只读取已成功持久化的最近 N 条消息（默认 10 条，`CHAT_HISTORY_MAX_MESSAGES`），按 `CHAT_HISTORY_MAX_CHARACTERS`（默认 4000 字符）从最近往前裁剪后拼入提示词，位置在「已授权知识证据」之前。历史不进入引用事件与引用持久化；读取失败只记日志并降级为无历史。
- 文档上传支持可选切片参数 `split_type`、`chunk_size`、`overlap`、`title_level`、`separator`、`regex`；缺省等价于 `TITLE` + `chunk_size=1000` + `overlap=100` + `title_level=6`。参数越界、正则不可编译或正则与分隔符同时出现时返回 422，且不落库、不落对象存储。
- P0 SSE 在建流前完成会话归属校验，以 Redis 分布式锁限制同一主体一条活动流；15 秒发送注释心跳，回答最长 120 秒。断线立即取消上游模型调用且不保存部分回答，P0 暂不支持 `Last-Event-ID` 续传；事件以递增 `sequence` 作为 SSE `id`。
- Agent 代码分析沙箱继续使用 Docker Python 3.13：每任务独立容器，CPU 1 核、内存硬上限 512 MiB、软预留 256 MiB、进程上限 128、临时目录 128 MiB、最长 90 秒、最大并发 1。
- 沙箱禁止 Docker Socket、宿主机目录、业务数据卷、`.env`、Git 元数据和默认网络；未获用户明确修改授权时不得写入项目工作区。

## 7. 部署、版本与运维

- 开发、测试、预生产和生产使用独立的密钥、Redis、索引和数据存储。
- 生产仅公开 HTTPS 入口；MySQL、Elasticsearch、MinIO、Neo4j、Redis、Agent 内部接口、Worker 与沙箱均不暴露公网端口。
- 实现时将 Python、FastAPI、Celery、Relier、Redis、MySQL、Neo4j、Elasticsearch、MinerU 与模型 SDK 的确切版本写入 lockfile 或镜像标签，不使用 `latest`。
- 监控任务积压、Phoenix 恢复、DLQ 深度、检索 P50/P95、首字时延、模型错误率、Token/成本、权限拒绝率及 SSE 断连率；日志以 JSON 输出并脱敏手机号、VIN、订单、凭据和回答证据中的敏感字段。
