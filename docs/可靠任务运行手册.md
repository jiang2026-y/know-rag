# 可靠任务运行手册

本文说明 P0 文档处理使用的 Celery + Relier 运行方式。认证 Session/锁 Redis 与任务 Redis 物理隔离；任务 Redis 只监听本机 `6380`，启用 AOF `everysec` 和 `noeviction`。

## 已实现的行为

- 上传文档先保存 MySQL 任务记录与 MinIO 原文件，再投递独立 Worker；FastAPI 重启不再把处理中任务直接标记失败。
- 若任务 Redis 短暂不可用，任务保持 `queued`；Celery Beat 每分钟扫描并在 Broker 恢复后补发，避免已持久化任务丢失。
- 同一交付轮次使用 Relier Redis Lua 幂等；MySQL 的 `queued -> processing -> completed/dead_lettered` 条件更新防止重复执行副作用。
- 单次文档任务软超时 15 分钟、硬超时 20 分钟，Worker 并发为 1，并启用 Phoenix 崩溃恢复及优雅关闭。
- 处理失败时最多自动重试 3 次；仍失败时将 MySQL 任务置为 `dead_lettered`，并由 Relier 写入 DLQ。
- DLQ 保留 7 天。Celery Beat 每小时清理过期记录；只有 `job=leader` 的在职员工能查询或重放文档处理死信。

## 首次配置

在项目根目录 `.env` 中确认以下值。开发环境可使用示例值；预生产和生产必须替换两个密码与 `RELIER_SECRET_KEY`。

```dotenv
TASK_REDIS_URL=redis://:你的任务Redis密码@127.0.0.1:6380/0
TASK_REDIS_PASSWORD=你的任务Redis密码
RELIER_SECRET_KEY=随机且仅任务运行时可见的密钥
```

`infra/redis/.env` 中的 `TASK_REDIS_PASSWORD` 必须与根目录 `.env` 一致。

## 启动顺序

在 PowerShell 的项目根目录执行：

```powershell
docker compose --env-file infra/redis/.env -f infra/redis/compose.yaml up -d task-redis
.\.venv\Scripts\celery.exe -A llmcopy.tasks.celery_app:celery_app worker --loglevel=INFO --concurrency=1
```

在第二个终端启动周期清理器：

```powershell
.\.venv\Scripts\celery.exe -A llmcopy.tasks.celery_app:celery_app beat --loglevel=INFO
```

最后按原方式启动 FastAPI。上传接口若任务 Redis 或 Worker 不可用，会返回可诊断的失败，不会在 Web 进程中悄悄执行任务。

## 死信管理与告警

- `GET /api/admin/tasks/dead-letter`：仅 leader 查询未过期死信任务。
- `POST /api/admin/tasks/dead-letter/{relier_task_id}/replay`：仅 leader 重放文档处理死信。
- Worker 离线超过 2 分钟、DLQ 深度大于 0、任一任务队列等待超过 10 分钟、近窗口失败率超过 5% 时应告警。Relier 已记录 Worker、Phoenix 与任务成功/失败指标；P0 需要由部署侧将这些指标接入现有监控平台。

## 每日备份

每天运行一次下列脚本。它只操作 `infra/redis/task-redis-backups` 目录，并删除该目录中超过 7 天的任务 Redis RDB 备份。

```powershell
.\scripts\backup_task_redis.ps1
```

建议使用 Windows 任务计划程序以服务账号每天执行；不得把 `.env`、认证 Redis 数据或 MinIO 数据卷加入该备份目录。
