# LLMcopy 项目交接文档（2026-07-22 存档）

更新时间：2026-07-22

本文面向没有任何前置上下文的新对话，说明项目当前已经实现的功能、运行依赖、关键设计、已知问题与建议的后续工作。除非特别标注为“未实现”或“待确认”，其余内容均已写入代码。

## 1. 项目目标与当前边界

LLMcopy 是一个知识库后端原型，当前完成了“文档入库 → MinerU 解析 → Markdown 父子切片 → 向量化写入 Elasticsearch”的主链路，并开始建设会话基础能力。

当前不包含完整的 RAG 检索问答链路：没有向量检索接口、没有命中子块后回查父块、没有主回答 LLM 服务、没有 SSE 流式回答接口。不要将“已完成向量写入”误认为“已完成知识库对话”。

## 5. 已实现：文档处理与向量化

### 5.1 上传与异步解析

接口：`POST /api/documents/upload`

表单字段：

- `file`：仅支持 PDF、DOC、DOCX。
- `upload_user`：上传用户标识，缺省为 `llmcopy`；也是上传锁的键。

流程：

1. 校验文件类型和大小，创建 `knowledge_document` 记录。
2. 上传源文件到 MinIO，创建 `document_processing_task` 任务。
3. 接口立即返回 `202 Accepted`、`task_id`、`document_id`。
4. 进程内后台任务调用 MinerU，取得 Markdown 和图片，写回 MinIO。
5. 切片、向量化完成后，任务状态为 `completed / vector_stored`；失败为 `failed`，可通过 `POST /api/documents/tasks/{task_id}/retry` 重试。

状态查询：`GET /api/documents/tasks/{task_id}`。

Markdown 预览与受控下载：

- `GET /api/documents/markdown/preview`
- `GET /api/documents/markdown/download`
- `GET /api/documents/images/download`

私有 MinIO 对象通过短期预签名 URL 下载，接口不会直接返回大文档内容。

### 5.2 父子分段

`MarkdownParentChildSplitter` 先根据 Markdown 标题（`#` 至 `######`）分段，再处理超长标题段。

- 普通标题段：长度不超过 `chunk_size`（默认 1000 字符），生成一个可向量化分段。
- 超长标题段：生成一个完整父分段和多个子分段。
  - 父分段保留完整原始 Markdown（含标题、表格语法、图片引用），`skip_embedding=1`，不生成向量。
  - 子分段按 1000 字符切分，默认重叠 100 字符，`skip_embedding=0`，每个子分段的 `metadata.parentChunkId` 指向父分段的 `chunk_id`。
- `metadata` 同时保存 `docId`、文件名、MinIO URL、标题层级、`chunkId` 等信息。

已验证：父块会完整保存，向量化查询会排除 `skip_embedding=1` 的父块，因此只对检索子块和普通块向量化。

限制：子分段按字符窗口直接截断，可能在 Markdown 表格或图片语法中间切开。这不影响后续给 LLM 的完整父块，但可能降低子块的检索语义质量。

### 5.3 MySQL 切片事务与批量写入

`KnowledgeSegmentRepository.replace_for_document` 使用单一 MySQL 事务：

1. `DELETE FROM knowledge_segment WHERE document_id = ?`；
2. 对全部切片执行 `executemany(INSERT ...)`；
3. 最后一次 `commit()`。

发生异常时连接关闭会回滚，因此不会留下“旧切片删掉但新切片只写入一部分”的状态。对于简单 INSERT，PyMySQL 通常会合并为多值 INSERT，以减少往返；不能把该行为当作绝对保证。

向量 ID 的批量回写也在一个事务中 `executemany(UPDATE ...)` 后提交。`knowledge_document` 和 `document_processing_task` 的部分仓储使用 `autocommit=True`，因此“创建文档、上传 MinIO、创建任务”不是跨 MySQL 与 MinIO 的全局事务；失败时依靠状态标记为 `failed` 做补偿。

### 5.4 Elasticsearch 向量写入

`DocumentVectorizationService.vectorize_document(document_id)` 的规则：

1. 文档不存在返回 `false`；文档已经是 `VECTOR_STORED` 返回 `true`。
2. 删除该文档在 ES 的旧向量。
3. 每页读取最多 100 条 `INIT`、`embedding_id IS NULL`、`skip_embedding=0` 的切片。
4. DashScope 批量生成 1536 维向量（每次模型请求最多 9 个切片）。
5. 使用 ES `_bulk` 写入 `know-engine`；ES `_id` 使用 `chunk_id`。
6. 回写 MySQL 的 `embedding_id` 与 `VECTOR_STORED`，全部完成后将文档标为 `VECTOR_STORED`。

ES 索引使用余弦相似度与 `int8_hnsw`。本地已创建过索引，首次写入逻辑也会确保索引存在。

## 6. 已实现：Redis 分布式锁

实现文件：`src/llmcopy/document/services/redis_distributed_lock.py`。

锁不是 Redlock 多节点算法，而是适用于当前单 Redis 容器的令牌互斥锁：

1. 进入临界区前执行 `SET key token NX EX 30`。
2. 获取失败立即抛出 `DistributedLockNotAcquiredError`，不轮询、不阻塞。
3. 锁持有期间自动续租。
4. `finally` 中通过 Lua 脚本比对随机 token 后删除，防止旧任务误释放新任务的锁。

锁键：

| 场景 | 锁键含义 | 作用 |
| --- | --- | --- |
| `document-upload` | `upload_user` | 同一用户不能同时提交多份上传 |
| `document-split` | `document_id` | 同一文档的切片与向量化不能并发 |

锁获取失败的上传请求返回 `409 Conflict`；Redis 不可达或密码错误时返回 `503 Service Unavailable`。切片、向量化发生在后台任务中，锁失败会使该任务标记为失败，可走原重试接口。

**尚需操作：** 当前 Docker Redis 已启用认证，但尚未获知/填写实际 `REDIS_PASSWORD`。不填该值时，任何实际使用锁的接口都会因 Redis 认证失败而返回 503；先配置密码再启动服务。

## 7. 已实现：会话与异步标题

数据库中已存在以下表（由外部先行创建，不在 `resources/sql` 中）：

- `chat_conversation`：`conversation_id` 唯一、`user_id`、`title`、`status`、创建/更新时间。
- `chat_message`：`message_id` 唯一、`conversation_id`、`type`（`USER` 或 `ASSISTANT`）、`content`、`metadata` 等。

接口：`POST /api/chat/conversations`

请求：

```json
{
  "user_id": "user-1",
  "first_message": "如何设计知识库检索系统？"
}
```

行为：

1. 去除空白后，将首句截取为不超过 20 个字符的临时标题。
2. 在一个 MySQL 事务中同时写入 `chat_conversation` 与首条 `chat_message(type=USER)`。
3. 立即返回 `201 Created`、会话 ID、临时标题和 `title_pending: true`。
4. 使用 `asyncio.create_task` 异步调用 `qwen3.5-flash`，System Prompt 明确要求只输出不超过 20 字的中文标题。
5. 请求参数为 `enable_thinking=false`、`max_completion_tokens=32`、`stream=false`、低温度，以获得快速且简短的响应。
6. 对模型返回结果去除空白、首尾引号并截断；只在数据库标题仍等于临时标题且会话为 `ACTIVE` 时更新，避免覆盖用户手工修改。
7. 模型调用、标题解析或数据库更新失败会被后台任务捕获，保留临时标题，绝不影响会话创建或未来的回答流。

项目当前没有主回答模型或 SSE 流式对话接口。标题服务已保证不等待模型结果，因此将来主回答流只需先调用会话创建服务，再继续输出即可。

## 8. 已讨论但未实现

### 8.1 检索命中子块后回查父块

目标流程：

```text
ES 检索命中子分段
→ 读取 metadata.parentChunkId
→ MySQL 查询对应父分段完整 text
→ 对父块去重、限制上下文长度
→ 将完整父块（含完整 Markdown 图片/表格引用）交给 LLM
```

目前缺失：ES 检索接口、MySQL 按 `chunk_id` 查询父块的方法、RAG 上下文组装服务、LLM 回答服务。父子“入库和向量化”已完成，但“子命中回父块给 LLM”没有完成。

### 8.2 雪花算法分段 ID

当前 `chunk_id` 使用 UUID 字符串，数据库字段 `knowledge_segment.chunk_id` 没有唯一索引。曾讨论改用雪花算法并增加唯一约束，但用户已明确“先不改动”，因此没有实现。

若后续实施，必须先确定多实例唯一的 `SNOWFLAKE_WORKER_ID` 分配方案，再实现单例、时钟回拨处理和数据库唯一约束；不能只在单进程内生成而忽略多实例冲突。

4. 没有对真实 DashScope、MinerU、MySQL、MinIO、ES 做端到端业务写入测试；已完成的是单元测试和容器/Schema 只读检查。接入真实凭证后应补充冒烟测试。
