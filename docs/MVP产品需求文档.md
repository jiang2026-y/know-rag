> 版本：v0.1（P0）｜日期：2026-08-04｜状态：待实施
>
> 配套文档：[技术栈选型](./技术栈选型.md) · [DDD 项目目录](./DDD项目目录.md) · [需求规格说明书](./需求规格说明书.md)

## 1. 产品概述

### 1.1 一句话定位

面向普通顾客、已购车车主和企业员工的 Web 智能问答平台：系统基于可信身份、受控企业知识和业务数据，提供带引用、可审计、按权限隔离的汽车领域回答。

### 1.2 背景与机会

车型资料、购车政策、使用手册、售后规范、车辆档案和员工技术资料通常分散在多个系统。用户需要一个统一入口，但通用聊天不能安全判断车主归属、员工岗位范围或资料可见级别。本产品的价值不只是“生成回答”，而是将身份、权限、知识检索、业务查询、引用与反馈编排为可追溯的服务闭环。

### 1.3 MVP 假设

1. 普通顾客愿意通过 Web 获取有明确资料来源的公开车型与服务咨询。
2. 已完成可信绑定的车主愿意使用平台查询本人车辆、订单和服务信息，前提是系统不会泄露他人数据。
3. 员工愿意使用按岗位范围过滤的内部知识与关系图谱，前提是权限边界可解释且可审计。
4. 结构化意图、受控数据源路由、混合检索和引用校验，比单次直接调用大模型更能降低错误回答与数据泄露风险。

### 1.4 P0 试点边界

P0 仅上线 **Next.js + TypeScript Web**。它必须完整支持三类用户的问答闭环，但钉钉机器人、移动端和其他渠道后置到 P1。

P0 使用 FastAPI `api_service` 作为身份、权限、业务数据与审计的可信边界；独立 `agent_runtime` 只通过内部 HTTP/JSON 调用受控工具。前端和 Agent 均不得直连 MySQL、Elasticsearch、MinIO、Neo4j 或业务 Redis。

## 2. 目标、非目标与成功定义

### 2.1 P0 目标

- 三类用户能在 Web 完成身份解析、提问、受控检索、流式回答、引用查看和反馈提交。
- 普通顾客只获得公开资料；车主只获得本人已授权车辆数据；员工只获得岗位范围内的内部资料与图谱结果。
- 文档可完成上传、审核、MinerU 解析、切片、向量化、Elasticsearch 索引和生命周期管理。
- 数据源或模型故障时，系统保留其他成功结果并提供明确降级文案，不猜测个人车辆信息或伪造引用。
- 所有关键请求、任务和回答事件可由 `trace_id` 关联审计。

### 2.2 P0 明确不做

- 钉钉、移动端、社区、评论、关注、多人协作、自动向外部系统写入或发布；
- 任意网页抓取、任意 SQL/Cypher、未经审核的外部资料、面向用户的通用代码执行；
- 本地模型、用户自定义模型 Provider、自动跨 Provider 路由或模型费用优化；
- 以静态角色、模拟车辆或默认内部权限替代真实身份、绑定和岗位授权；
- 未经确认的数据保留、导出、删除和合规策略。

### 2.3 发布质量门槛

P0 发布前必须满足以下质量门槛；试点转化率、满意度、成本预算和服务等级目标在获得真实业务数据后另行确认。

- 三类角色越权读取为 0；身份、权限或绑定校验故障时只能访问公开知识。
- 每个发布回答都有可鉴权来源，或明确标记证据不足、冲突或暂不可查询。
- Worker 中断、重复投递、超时和毒丸任务能按状态机恢复、失败或进入 DLQ，且不产生重复业务副作用。
- 沙箱无宿主机、密钥、业务数据或内部网络访问能力。
- 查询、检索、模型、任务和 SSE 事件均可通过 `trace_id` 定位。

## 3. 用户与使用场景

### 3.1 目标用户

| 用户 | 核心需求 | 主要限制 |
| --- | --- | --- |
| 普通顾客 | 查询公开车型、配置、购车、门店和售后信息。 | 不访问车主、订单或内部资料。 |
| 已购车车主 | 查询本人车辆的保养、质保、订单、服务与通知。 | 必须由服务端验证绑定；不访问他人车辆或内部资料。 |
| 企业员工 | 查询岗位授权的制度、技术、销售、售后和图谱关系。 | MySQL 账号认证与岗位范围必须可信；不访问跨岗位敏感数据。 |

### 3.2 核心 JTBD

> 当我需要汽车产品、车辆服务或内部业务知识时，我希望系统按我的真实身份只检索有权访问的信息，并给出能回溯来源的回答，使我不必在多个系统间反复查找，也不用担心看到不该看的数据。

### 3.3 典型场景

1. **公开咨询：**普通顾客询问某 SUV 的续航和安全配置，系统仅检索公开手册或官方资料并展示引用。
2. **车主服务：**已认证车主询问保养时间，系统根据服务端确认的车辆范围检索保养规则与本人车辆档案；个人数据不可用时明确说明暂不可查询。
3. **员工技术支持：**员工询问某零部件关联的故障码，系统在岗位权限允许时合并 Neo4j 关系与内部技术资料，并展示受控内部引用。
4. **非领域问题：**任意用户询问天气，系统转入通用对话，不读取任何企业私有上下文。

## 4. 产品原则与体验约束

- **权限先于检索：**身份、车辆范围、员工范围和知识范围先由服务端构造，再调用任何数据源。
- **引用优先：**回答只使用已授权证据；找不到来源时明确说明限制，不能伪造引用。
- **最小化暴露：**前端只调用 `/api/v1`，浏览器不持有模型、数据库、图数据库、Redis 或 Agent 工具凭据。
- **失败可理解：**模型、数据源或任务失败时显示安全文案、状态和可操作的重试入口，不无限加载。
- **可靠异步：**文档、向量化、索引、审计和反馈任务使用 Celery + Redis + Relier；业务幂等仍由唯一约束和状态机保证。
- **Agent 受限：**Agent 只能调用预定义内部工具；不能直接查询业务数据、拼接 SQL/Cypher 或借沙箱绕过权限。

## 5. MVP 核心流程

```text
Web 访问
  ↓
顾客或员工 MySQL 账号密码认证 / 服务端 Session 身份解析
  ↓
api_service 构造 AccessContext、车辆范围、员工范围和知识范围
  ↓
提交问题并创建会话消息
  ↓
qwen3.5-flash：意图识别、查询改写与查询路由
  ↓
受控工具并行检索 Elasticsearch / MySQL 只读数据 / Neo4j
  ↓
父子块补全、二次授权、qwen3-rerank 重排
  ↓
qwen3.7-plus：带引用 SSE 回答
  ↓
保存查询、证据、引用、反馈、任务状态与 trace_id
```

### 5.1 最小状态机

- 文档：`queued → processing → converted → chunked → vector_stored`，或进入 `failed/cancelled`。
- 异步任务：`queued → running → succeeded`，或进入 `failed/cancelled/dead_lettered`；Phoenix 恢复和手动重试保留尝试记录。
- 会话：创建、活动、关闭或归档；任何读取均重新校验归属和权限版本。
- 身份权限：员工 `status`、`job` 或 `dept_id` 变更后，后端立即撤销该员工的全部 Redis Session；旧会话、缓存和检索结果不得继续作为私有授权依据。

## 6. 功能需求

优先级：**P0** 为 Web 首次发布阻断项，**P1** 为首轮试点后的扩展项。

### 6.1 身份、车辆与员工访问控制

| ID | 优先级 | 需求 | 验收要点 |
| --- | --- | --- | --- |
| FR-01 | P0 | 普通顾客使用服务端 Session 与 HttpOnly Cookie 访问 Web。 | Cookie 不保存角色和权限；未认证或无有效绑定时仅能访问公开知识。顾客密码使用 Argon2id；修改密码后立即撤销该顾客全部 Redis Session。 |
| FR-02 | P0 | 企业员工使用现有 MySQL 账号密码完成身份认证。 | 以 `staff_info.emp_id` 识别员工；仅 `status=ON_JOB` 且密码校验通过时建立可信 Session。`job` 仅使用 `staff`、`leader` 两个固定值；新密码使用 Argon2id，旧 PBKDF2 登录成功后自动升级；禁用或部门变更后，后端立即清除受影响 Redis Session。 |
| FR-02A | P0 | HR 系统为已创建员工设置初始密码。 | 仅内部 HR 服务携带 `X-Internal-Service-Token` 和 `Idempotency-Key` 调用；目标必须是已存在、`status=ON_JOB` 且密码为空的员工。本项目仅生成 Argon2id 摘要，不创建员工或修改 HR 主数据；成功后撤销目标 Redis Session，幂等记录保留 24 小时、无敏感审计保留六个月。 |
| FR-03 | P0 | 车主和员工权限由 MySQL 可信数据计算。 | P0 员工仅按在职状态及 `job=staff`、`job=leader` 分类；`dept_id` 可维护但暂不参与知识授权。车辆范围和员工范围均不可由客户端提交或扩大。 |
| FR-03A | P0 | 在职且 `job=leader` 的管理员可修改普通员工 `status`、`dept_id`。 | 目标必须为当前 `job=staff` 的员工，接口拒绝修改 `job`；必须使用 `Idempotency-Key`，幂等记录保留 24 小时；MySQL 更新成功后立即撤销目标员工全部 Redis Session，并保存六个月审计记录。 |
| FR-04 | P0 | Neo4j 仅用于关系图谱投影和受控查询。 | 图谱异常、同步延迟或无权限时不放宽访问，按最小权限降级。 |

### 6.2 知识管理与检索

| ID | 优先级 | 需求 | 验收要点 |
| --- | --- | --- | --- |
| FR-05 | P0 | 在职员工可上传 PDF、DOC、DOCX、CSV、XLS、XLSX；先经 MinerU 解析，再由领导审核发布。 | 上传者不能自行配置范围；文档解析后进入 `PENDING_REVIEW`，仅 `leader` 可选择 `VISITOR`、`STAFF` 或 `LEADER` 并触发向量化。驳回文档不得进入 Elasticsearch。待审核、驳回文档仅上传者和领导可查看。 |
| FR-06 | P0 | 文档经 MinerU 转换、父子切片和 DashScope `text-embedding-v4`（1536 维）写入 ES。 | 失败文档不得进入可检索状态；模型、维度和版本可追溯。 |
| FR-07 | P0 | ES 支持向量、中文全文和 metadata 混合召回。 | 检索前按知识范围过滤；命中子块后回溯父块、补全兄弟块并二次授权。 |
| FR-08 | P1 | 完善 CSV/Excel、扫描件、图片附件和解析质量规则。 | 实施前完成格式、OCR、文件上限和验收标准确认。 |

### 6.3 问答、引用与受控数据源

| ID | 优先级 | 需求 | 验收要点 |
| --- | --- | --- | --- |
| FR-09 | P0 | 使用 `qwen3.5-flash` 输出结构化意图并执行查询改写。意图固定为 `related`、七类意图、八项实体及不超过 200 字的 `reasoning`；改写按简洁化、抽象化、错别字纠正三步执行。 | 仅汽车相关问题调用改写并进入 ES；改写失败使用原查询；原查询保存在 `chat_message.content`，改写结果写入同一消息 `metadata.queryRewrite`；不生成、展示或记录完整思维链。 |
| FR-10 | P0 | 按意图路由知识库、MySQL 只读数据、Neo4j 或通用对话。 | 每个 Adapter 限制权限、表/列或标签/关系、行数、超时和审计。 |
| FR-11 | P0 | 使用 `qwen3-rerank` 对统一证据结果重排。 | 保存原始分数、重排分数、淘汰原因、数据源和权限结论。 |
| FR-11A | P0 | ES 命中在送入回答模型前回 MySQL 二次授权并补全父子块上下文。 | 当前文档必须为 `VECTOR_STORED` 且其 `accessible_by` 属于可信主体范围；短父块完整补回，长父块先补前后各一块，边界未结束时最多各补两块，且总上下文不超过 12000 字符。 |
| FR-12 | P0 | 使用 `qwen3.7-plus` 基于已授权向量证据生成带引用回答。 | 每次最多 1024 输出 Token；回答引用与服务端保存的引用清单一一对应；模型失败、取消或空回答均不得保存部分助手消息。 |
| FR-13 | P0 | 非汽车领域问题不使用企业数据。 | 不向模型携带车主、员工、知识库、订单或图谱上下文。 |

### 6.4 Web、SSE 与反馈

| ID | 优先级 | 需求 | 验收要点 |
| --- | --- | --- | --- |
| FR-14 | P0 | Next.js Web 提供公开入口、顾客/员工登录、会话、问答、文档管理、任务与反馈页面。 | 页面只调用 FastAPI `/api/v1`；Next.js 不复制领域规则或直连数据源。 |
| FR-15 | P0 | SSE 输出 `progress`、`query_rewrite`、`answer_delta`、`citation`、`error`、`done`。 | 查询开始先发送“正在优化您的问题”，随后返回原查询、改写查询和增强查询；所有事件含递增序号和 `trace_id`；15 秒心跳，最长 120 秒；同一主体只允许一条活动流。断线立即取消，不支持 P0 断线续传。 |
| FR-16 | P0 | 用户可对完整助手回答提交“赞”或“踩”，并允许修改评价。 | 反馈关联会话、消息、引用、权限快照和模型版本；同一主体对同一回答仅保留最近一次评价，更新后保留一年；重复请求具备 24 小时幂等性。 |
| FR-17 | P1 | 钉钉机器人和其他渠道接入。 | 复用统一会话与权限模型，不复制业务规则。 |

### 6.5 Agent、任务与安全沙箱

| ID | 优先级 | 需求 | 验收要点 |
| --- | --- | --- | --- |
| FR-18 | P0 | 独立 Agent Runtime 通过内部 HTTP/JSON 调用 FastAPI 工具。 | Agent 不持有业务数据源凭据，工具调用由 FastAPI 重新授权、脱敏和审计。 |
| FR-19 | P0 | 文档、Embedding、索引、审计和反馈使用 Celery 5.4+、Redis 7+、Relier 0.1 系列。 | Redis 启用 AOF 和 `noeviction`；任务具备幂等键、DLQ、Phoenix 恢复和优雅关闭。 |
| FR-20 | P0 | 所有可能产生副作用的写接口使用 `Idempotency-Key`。 | 重复且请求一致时返回首个结果；键相同但请求不同返回冲突。 |
| FR-21 | P0 | Agent 代码分析仅在用户明确请求时进入 Docker Python 3.13 沙箱。 | 非 root、只读、无网络、白名单文件、单次容器、CPU 1 核、内存 512 MiB、进程 128、临时目录 128 MiB、90 秒和单并发。 |

## 7. 用户故事与验收场景

### US-01：普通顾客公开咨询

**作为**普通顾客，**我希望**查询公开车型信息，**以便**了解产品和服务而不暴露其他人的数据。

- Given 未绑定车辆的用户，When 询问车型配置，Then 系统仅查询公开知识并返回带公开来源的回答。
- Given 普通顾客请求他人订单或维修记录，When 提交问题，Then 系统拒绝或仅说明无权访问，不透露记录是否存在。

### US-02：车主专属服务

**作为**已购车车主，**我希望**查询本人车辆的保养或质保信息，**以便**获得可信服务建议。

- Given 服务端确认当前用户与车辆绑定，When 询问保养时间，Then 系统只查询被授权车辆和对应规则。
- Given 绑定校验失败或车辆数据源不可用，When 提问，Then 系统不猜测车辆状态，仅提示暂不可查询个人车辆信息。

### US-03：员工内部技术支持

**作为**企业员工，**我希望**查询岗位相关的技术资料和关系图谱，**以便**完成业务支持。

- Given 员工 MySQL 账号认证与岗位范围有效，When 查询零部件和故障码关联，Then 系统按图空间和知识范围返回受控证据。
- Given 员工跨岗位范围提问，When 检索，Then 系统排除无权资料和关系，不因图谱存在关联而放宽授权。

### US-04：可靠的流式回答

**作为**任意授权用户，**我希望**在回答生成时看到进度、引用或错误，**以便**知道请求是否完成。

- Given 回答正常生成，When SSE 连接建立，Then 前端按顺序显示增量文本、已确认引用和完成事件。
- Given 一个数据源失败，When 其他来源仍有证据，Then 系统保留成功结果并在回答中说明限制。
